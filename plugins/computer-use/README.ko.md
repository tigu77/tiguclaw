# computer-use — 컴퓨터 사용 (화면 관측 + 조작)

비서가 **지금 화면을 찍어서 보고, 그 화면을 누른다.**

> ★조작은 **되돌릴 수 없다.** 이 플러그인을 켜는 것은 «비서에게 이 기계의 마우스와
> 키보드를 준다» 는 뜻이다. 무엇을 묻고 무엇을 자동으로 하는지는
> `skills/computer-use/SKILL.md` 가 정한다.

## 켜기 전에 — 기계마다 걸리는 것이 다르다

**macOS** 는 권한이 **둘**이고, 서로 다르다.

    화면 기록      시스템 설정 → 개인정보 보호 및 보안 → 화면 기록      ← 관측
    손쉬운 사용    시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용    ← 조작

둘 다 «데몬을 실행하는 앱» 을 켜고, **그 뒤 데몬을 한 번 재시작**해야 반영된다.
★관측만 되고 조작이 안 되는 상태가 정상적으로 존재한다 — 권한이 다르기 때문이다.

**Windows** 는 화면·입력에 권한 동의가 **없다.** 대신 **세션**이 그 자리를 차지한다 —
데몬이 서비스(Session 0)로 떠 있으면 사용자 화면이 아예 보이지 않고 입력도 닿지 않는다.
로그인한 사용자 세션에서 실행되어야 한다.
★그리고 **관리자 권한으로 뜬 창**(UAC 대화상자 등)에는 입력이 **조용히 안 닿는다.**
미리 알 방법이 없어서 막지 못한다 — 재관측이 유일한 판정이다.

★어느 쪽이든 도구는 **매달리지 않고 곧바로 안내를 돌려준다**(mac 실측 71~93ms).
 이게 중요한 이유: MCP 도구 호출 천장이 11분이라, 매달리면 턴이 그만큼 묶인다.

## 할 수 있는 것

**관측** — 전체 화면(주 디스플레이) · 특정 디스플레이 · **영역**
(★화면 밖 영역은 거절하고, 가장자리에 걸치면 **화면 안쪽만** 찍고 그 사실을 말한다)

**조작** — 클릭(더블·우클릭 포함) · 글자 입력(한글 그대로) · 키 조합 · 드래그 · 스크롤.
전부 **수식키를 누른 채**로 할 수 있다(`shift`+드래그, `ctrl`+클릭, `alt`+스크롤).

## 안전 장치 — 조용히 실패하지 않게

- **사람이 쓰는 중이면 조작하지 않는다.** 방금까지 사용자가 키보드·마우스를 썼으면 막는다.
- **좌표는 «관측 그림의 픽셀»** 이고, 그 그림의 «화면 id» 를 같이 줘야 한다.
  ★**조작을 한 번 하면 그때까지의 화면 id 가 전부 무효**가 된다 — 화면이 바뀌었으니까.
  낡은 그림 좌표로 누르는 길이 구조적으로 막혀 있다.
- **같은 기계를 둘이 동시에 만지지 못한다**(작업 하나가 쥐고 있으면 다른 쪽은 기다린다).
- **실패하면 «했다» 고 말하지 않는다.** 왜 막혔는지와 무엇을 하면 되는지를 돌려준다.
- 계획이 눌러둔 키·버튼은 **취소되어도 떼어진다**.

## 제어 표시와 중지 — 사용자가 언제든 멈춘다 (macOS · Windows)

비서가 조작을 시작하면(첫 `do`) 화면에 **제어 중 표시**가 뜬다 — 화면 가장자리의 넓고 부드러운 주황 빛(가운데는 투명) · 위쪽 가운데
**중지 단추**(양끝이 둥근 작은 캡슐 «조작 중 · 눌러서 중지») · **실제 마우스 포인터**
둘레 고리(가짜 포인터를 그리지 않는다 · 버튼이 눌린 순간 굵어져 클릭 자리가 보인다). 비서가 그 기계의 제어권을 쥐고 있는
동안 떠 있다 — 연달아 하는 조작·화면 보기 사이에는 유지되고, **그 작업(대화의 답·매니저·서브 실행)이 끝나면 바로** 테두리·고리·단추가
함께 내려간다. 끝났다는 신호가 오지 않는 경우(대화창 `/stop`·작업 취소 등)에는 마지막 조작 뒤 60초에 내려간다.

- **포인터는 순간이동하지 않는다** — 클릭·스크롤·드래그 전에 실제 포인터가 지금 자리에서 목표까지 짧게(길어야 약 0.1초, 목표 직전에 느려진다)
  미끄러져 간다. 화면을 보는 사람이 «어디로 가서 누르나» 를 따라갈 수 있다.
- **표시를 화면 캡처에서 빼지 않는다** — 화면 공유·원격 접속 도구는 대개 화면을 캡처해 보내므로, 빼면 원격으로 보는 사람에게
  표시가 안 보인다(11-24 원격 시험에서 실제로 안 보였다). 원격 도구 화면에 실제로 보이는지는 아직 사람 눈으로 확인하지 않았다.
  비서가 찍는 화면(`look`)에도 표시가 찍힐 수 있어, 비서에게는 «보이면 그건 화면 내용이 아니라 조작 표시» 라고 함께 알린다.
- **중지 단추를 누르면**(그 컴퓨터 앞에서든 원격 화면에서든) 진행 중인 조작은 다음 단계 경계에서 멈추고(붙여넣기·드래그·
  글자 한 덩이는 끝낸 뒤 — 키·버튼·클립보드가 남지 않게, 기다림·포인터 이동은 그 자리에서), 비서가 눌러둔 키·버튼을 놓고,
  표시를 내린다. 단추를 눌러도 앞 창은 바뀌지 않고, 그 클릭은 아래 창으로 새지 않는다.
- **단추는 사람의 클릭을 언제나 받는다**(통과시키는 때가 없다). 비서가 단추 자리를 눌러야 하면, 조작을 **보내기 전에**
  단추를 반대쪽(위↔아래)으로 비키게 하고 **옮겨진 것을 확인한 뒤에만** 보낸다. 비키지 못하면 그 표시를 내리고 **꺼진 것을 확인한 뒤에**
  보낸다(다음 조작에서 다시 뜬다). 꺼진 것도 확인하지 못하거나 위·아래 두 자리 모두에 누를 곳이 있으면 그 조작은 보내지 않고 이유를
  알린다 — 비서의 클릭이 «중지» 가 되거나 사람의 중지 클릭이 아래 앱으로 새지 않게.
- 그 뒤 **사용자가 새 메시지를 보낼 때까지** 비서는 조작하지 않는다(화면 보기는 된다). 중지 전에 보낸 메시지로는 풀리지 않는다.
- **대화창의 `/stop`** 은 진행 중인 조작을 끊는 또 하나의 길이다(눌린 키·버튼은 놓는다). 이때는 끝났다는 신호가 없어 표시가 마지막 조작 뒤 60초에 내려간다.
- **Esc 는 안내하지 않고, 중지 수단으로 의존하지 않는다.** 하드웨어 키보드의 Esc 상태를 짧게 조회해 잡히면 같은 멈춤으로 다루지만
  (최선 노력 · 직접 연결 키보드로는 아직 확인 안 함), 11-24 macOS 원격 시험에서 원격 접속 도구로 보낸 Esc 는 하드웨어 키 상태에 남지
  않아 잡히지 않았다(그 환경·그 도구에서의 관측). 감지는 **Esc 한 키의 상태만** 묻고(다른 키를 받지 않는다) 누른 Esc 는 앞 창에도
  그대로 간다. 비서가 보낸 `esc` 키도 같은 멈춤으로 잡힐 수 있어 멈춤 안내는 «사용자가 눌렀다» 고 단정하지 않는다.
- 표시를 띄우지 못하면 조작은 그대로 하지만 **단추도 Esc 도 없다** — 그때는 대화창의 `/stop` 이 멈추는 길이다.
- **Windows**: 표시는 첫 조작 때 내장 `csc.exe` 로 작은 프로그램(`%LOCALAPPDATA%\tiguclaw\tiguclaw-indicator-…exe`)을
  한 번 컴파일해 띄운다 — 그 몇 초 동안은 표시도 단추도 없다. 컴파일·기동이 실패하면(백신 차단일 수도, 컴파일러·정책 문제일 수도 있다)
  로그에 «표시 도우미 … 실패» 가 남고 조작은 그대로 한다 — 그동안은 위와 같이 **단추도 Esc 도 없고 대화창의 `/stop` 이 멈추는 길**이다.
  컴파일이 실패하면 매 조작마다 다시 하지 않고 1분부터 두 배씩(최대 30분) 쉬었다가 다시 해 본다 — 그 사이 프로그램이 생기면 바로 쓰고,
  성공하면 간격은 사라진다.
- ★실기: macOS 에서 빈 테스트 창으로 일부를 확인했다(개발 기록). ★미확인: 원격 접속 도구 화면에 실제로 보이는지(사람 눈) ·
  실제 원격 도구의 클릭 · 직접 연결 키보드의 Esc · 다중 모니터·전체 화면 공간.
- ★**Windows 는 제품 경로 일부를 실측했다**(격리 Windows Sandbox 게스트 한 대, 개발 기록 2026-11-24): 표시 도우미 컴파일·표시,
  고리 따라가기, 중지 단추 신호와 그 클릭이 아래 창으로 새지 않음, 실제 플러그인 배선에서 진행 중인 조작이 중지로 멈추고(남은 입력 0)
  눌린 키를 놓고, 새 메시지 전까지 조작을 거절했다가 그 뒤 다시 허용함. ★다만 그때의 중지 클릭과 새 메시지는 **합성**이었다
  (게스트 안 입력 주입 · 서비스에 직접 넣은 메시지). 눌린 키를 놓기까지 중지 클릭 뒤 3.76초가 걸렸다(그 기록에서 대부분은 해제용
  PowerShell 기동 — 모든 환경의 고정값은 아니다). ★미확인: 사람의 물리 클릭·Esc · 실제 대시보드/텔레그램 메시지 · 데몬 전체 부팅 ·
  다중 모니터·배율 · 원격 접속 화면에서의 표시 · Alt+Tab · 강제 종료 뒤 남는 프로세스 · Windows 정상 러너의 전체 회귀.

★그래도 **«보냈다» 가 «됐다» 는 아니다** — 앱이 그 단축키를 안 받거나, 스크롤이 끝에 닿아
있거나, 권한이 높은 창이면 입력은 나갔는데 아무 일도 안 일어난다. **판정은 재관측이다.**

## 못 하는 것

- **특정 창만** 찍기·창 고르기 — 창 열거가 아직 없다(전체 화면·디스플레이·영역까지)
- **Linux(X11/Wayland)** — 구현이 없다. 실행부가 없는 기계에선 도구가 아예 안 뜬다
  (있는 척하고 실패하지 않는다)

## 어느 기계에서 되나

| | 관측 | 조작 | 제어 표시·중지 |
|---|---|---|---|
| macOS | 구현·실사용 | 구현·실사용 (손쉬운 사용 권한 필요) | 구현 · 실기 일부 확인 |
| Windows | 구현 · 실기 확인(모니터 2개·DPI v2) | 구현 · 실기 확인(모니터 2개, 보조 화면 클릭 포함) | 구현 · 제품 경로 일부 실측(격리 게스트 · 합성 중지·메시지) — 물리 입력·실제 채널·전체 회귀 미확인 |
| Linux(X11/Wayland) | 없음 — 도구가 안 뜬다 | 없음 | 없음 |
