# computer-use — 컴퓨터 사용 (1단계: 화면 관측, 읽기 전용)

비서가 **지금 화면을 찍어서 본다.** 클릭·입력은 하지 않는다.

## 켜기 전에 — 기계마다 걸리는 것이 다르다

**macOS** 는 **화면 기록** 권한 없이는 캡처를 거절한다(종료코드 1 · `could not create image`).

    시스템 설정 → 개인정보 보호 및 보안 → 화면 기록 → 데몬을 실행하는 앱을 켠다
    그 뒤 데몬을 한 번 재시작한다

**Windows** 는 화면 캡처에 권한 동의가 **없다.** 대신 **세션**이 그 자리를 차지한다 —
데몬이 서비스(Session 0)로 떠 있으면 사용자 화면이 아예 보이지 않는다. 로그인한 사용자
세션에서 실행되어야 한다.

★어느 쪽이든 도구는 **매달리지 않고 곧바로 안내를 돌려준다**(mac 실측 71~93ms).
 이게 중요한 이유: MCP 도구 호출 천장이 11분이라, 매달리면 턴이 그만큼 묶인다.

## 지금 할 수 있는 것

- 전체 화면(주 디스플레이) · 특정 디스플레이 · **영역**
  (★화면 밖 영역은 거절하고, 가장자리에 걸치면 **화면 안쪽만** 찍고 그 사실을 말합니다 —
   Windows 처럼 화면 배치를 아는 기계에서)
- 결과는 그림 + 메타(시각 · 영역 · 크기 · 저장 경로 · **확인된 제한**)
- 프레임은 `<홈>/plugins/computer-use/` 에 JPEG 으로 남는다 — 스레드별 최근 10장, 7일(**잠정값**)

## 아직 못 하는 것

- **특정 창만** 찍기 — 창 열거가 1단계 밖이다(손쉬운 사용 권한 또는 네이티브 호출 필요)
- **클릭·입력** — 2단계
- **Linux(X11/Wayland)** — 구현이 없다. 실행부가 없는 기계에선 도구가 아예 안 뜬다
  (있는 척하고 실패하지 않는다)

## 어느 기계에서 되나

| | 관측 | 비고 |
|---|---|---|
| macOS | 구현·실사용 | 화면 기록 권한 필요 |
| Windows | 구현 · **실기 확인**(2026-09-17, 모니터 2개·DPI v2) | PowerShell + .NET. 사용자 세션 필요 |
| Linux(X11/Wayland) | 없음 | 도구가 안 뜬다 |

클릭·입력(2단계)은 **어느 기계에서도 아직 없다.**

## 프레임은 어떻게 남나

- 자리: `<홈>/plugins/computer-use/` — 플러그인을 지우면 같이 지워집니다
- 형식: JPEG(긴 변 1600px, 품질 80). 같은 화면 기준 PNG 대비 **약 6배 작고**, 작은 글자는
  그대로 읽힙니다
- 데이터베이스에는 **경로만** 들어갑니다(그림 자체는 안 들어갑니다)
