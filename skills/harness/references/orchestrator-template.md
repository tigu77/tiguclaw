# 오케스트레이션 스킬 템플릿

**반복해서 사용할 팀을 제작할 때** 필요한 부분만 채우는 예시다. 기존 역할을 재사용하고
QA를 자동 추가하지 않는다. 일반 위임·매니저 배치는 SYSTEM.md §1, 도구 계약은 현재
도구 설명, 개별 스킬 형식·description은 `skill-creator`, 실행 검증은 `verify`를 따른다.

## 1. 표준 템플릿

아래 `{...}`는 실제 역할·경로·가용 프로파일로 치환한다. 프로젝트 전용 팀은
`project_capabilities(path)`로 발견한 폴더를 로드·위임 호출의 `path`에도 지정한다.

```markdown
---
name: {domain}-orchestrator
description: "{도메인} 재사용 팀을 조율한다. {초기 실행 요청}, {도메인} 결과 수정·부분 재실행·보완·이전 결과 개선 요청 시 사용."
---

# {Domain} Orchestration

## 구성 멤버

| 에이전트 | model 프로파일/직접 지정 | 역할 | 입력 | 출력 | 필수/선택 |
|---|---|---|---|---|---|
| {agent-1} | {실제 가용 프로파일 또는 provider:model} | {역할} | {입력 소스} | {절대 경로}/01_artifact.md | 필수 |
| {agent-2} | {실제 가용 프로파일 또는 기본 모델} | {역할} | {01_artifact.md} | {절대 경로}/02_artifact.md | {필수/선택} |

## 작업 분류
- 신규 전체 → 전체 파이프라인
- 부분 수정 → 영향받는 역할과 그 출력에 의존하는 단계만 재실행

## 워크플로우

### Phase 0: 컨텍스트 확인
1. 기존 작업 폴더와 이전 산출물·입력의 관련성을 확인한다.
2. 초기 실행은 새 작업 폴더를 선택한다.
3. 부분 수정은 이전 산출물 절대 경로와 변경 범위를 해당 역할에 전달한다.
4. 새 입력은 기존 폴더를 옮기거나 덮지 않고 새 실행 하위 폴더를 선택한다.

### Phase 1: 준비
1. 입력과 완료 기준, 각 산출물의 필수/선택 여부를 확인한다.
2. 기존 폴더 관례 안에서 충돌 없는 작업 경로를 정하고 입력을 기록한다.

### Phase 2: 위임·연결
1. 헌법에 따라 배치된 지휘자가 현재 도구 설명대로 위임·합류한다.
2. 각 프롬프트에 역할·입력·출력 절대 경로·프로젝트 path·실패 보고를 명시한다.
3. 독립 단계만 병렬로 수행한다. 선행 필수 산출물의 존재·유효성을 확인한 뒤 종속 단계를 시작한다.

### Phase 3: 통합·검증
1. 반환값/파일을 수집하고 입력·출력 계약 및 완료 기준을 대조한다.
2. QA 역할을 선택했다면 해당 역할에 범위·산출물을 전달한다. 아니면 지휘자가 검증한다.
3. 필수 산출물/검증 실패 시 종속 단계와 최종 완료를 차단하고 막힌 원인을 보고한다.
4. 선택 산출물만 없으면 누락과 영향 범위를 밝힌다. 필수 조건을 충족한 결과만 완료로 보고한다.

### Phase 4: 보고
중간 산출물은 보존하고, 최종 결과·검증·미검증·막힘을 구분해 보고한다.

## 데이터 흐름
입력 → {agent-1} → 01_artifact.md → {agent-2} → 02_artifact.md → 통합
각 화살표의 필수/선택 입력과 소비자를 위 역할 표에 연결한다.

## 실패 처리
- 필수 산출물 실패/부재/계약 불일치: 종속 단계 차단. 원인과 복구 경로를 보고한다.
- 선택 산출물 실패: 독립된 나머지만 진행하고 누락·영향을 보고한다.
- 재시도는 원인과 기존 실행 상태를 확인한 후 정한 상한 내에서만 한다. 실행 중 작업은 재발주하지 않는다.
- 상충 결과는 출처를 병기한다. 삭제·이동·외부 영향은 사용자 승인 없이 실행하지 않는다.

## 테스트 시나리오
- 정상: 필수 입력 → 역할 출력 → 다음 입력 → 완료 기준 연결 확인
- 오류: 필수 출력 부재 시 종속 단계·완료 보고가 차단됨
- 선택 출력을 둔 경우: 그 누락을 필수 실패와 구분해 보고함
```

## 2. 후속 작업과 데이터 전달

- 폴더 존재만으로 재사용을 결정하지 않는다. 요청·입력·기존 산출물이 같은 작업인지 확인한다.
- 부분 재실행은 앞선 산출물을 읽어 피드백을 반영하고, 변경된 출력의 소비자도 확인한다.
- 새 실행은 기존 관례에 맞는 새 하위 폴더(예: `_workspace/<run-id>/`)를 사용한다.
  기존 폴더 이동·삭제·덮어쓰기는 자동 수행하지 않는다.
- 파일 전달은 생산자와 소비자에 같은 절대 경로를 준다. 짧은 결과는 `wait_for_worker` 반환값으로
  지휘자가 수집할 수 있다. 반환값을 파일에 기록할 담당자와 도구 권한도 맞춘다.
- 프로젝트 작업은 그 프로젝트의 작업 폴더 관례를 따른다. 미등록 프로젝트의 기본 위치 등은
  SYSTEM.md §1·§5를 참조하고 여기서 다른 경로 규칙을 만들지 않는다.

## 3. 확장·검증 체크

기존 역할을 확장하면 역할 표·의존성·입출력과 후속 요청 description을 함께 갱신한다.
새 QA·새 스킬·새 폴더를 자동으로 늘리지 않는다. `verify`로 정상/필수 실패 연결과 기존 호출을
규모에 맞게 확인한다. **변경 이력은 `git log`**로 남긴다.
